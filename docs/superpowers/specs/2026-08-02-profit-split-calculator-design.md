# Profit Split Calculator — Design Spec

Date: 2026-08-02

## Purpose

A pure front-end PWA calculator. User enters 4 numbers; the page live-computes
every step of a profit-split chain and highlights one final result
("Monthly Payout"). Deployed as a static site on GitHub Pages.

## Inputs (user-provided)

| Field | Meaning | Type |
|---|---|---|
| `principal` | Principal amount (RM) | number, no upper bound |
| `monthlyRate` | Monthly rate, entered as a plain percent number (e.g. `5` = 5%) | number |
| `period` | Number of months | number |
| `costOfFund` | Cost of fund, entered as a plain percent number | number |

## Constants (hardcoded, not exposed as input or as explanatory text in the UI)

```
takaful       = 1%
sjRatio       = 40%
myRatio       = 60%
investorSplit = 50%
myTeamCount   = 4
```

These raw constants (40/60, ÷4, etc.) must never appear as literal explanatory
text anywhere in the UI. Only the *computed results* of formulas that use them
are shown.

## Calculation chain (in order)

```
annualRate       = monthlyRate * period
balanceInterest  = annualRate - costOfFund
afterTakaful     = balanceInterest - takaful
investorReturn   = afterTakaful * investorSplit
sjTeamReturn     = afterTakaful - investorReturn
sjInterest       = sjTeamReturn * sjRatio
myInterest       = sjTeamReturn * myRatio
myInterestAmount = principal * myInterest
myTeamAmount      = myInterestAmount / myTeamCount
myMonthly         = myTeamAmount / 12
```

All percentage-valued variables (`annualRate` through `myInterest`) also have a
derived RM amount = `ratio * principal`, shown alongside the ratio.
`myInterestAmount`, `myTeamAmount`, and `myMonthly` are already RM amounts by
their own formula — they are shown as RM only, not multiplied by principal
again.

## Negative-value handling

After computing the chain in order, scan the 7 ratio variables in sequence.
The **first** one that is negative is the "root cause." All rows from that
point downward (which will cascade negative) render with red text. A custom
dark-themed modal (not a native `alert()`) opens naming the root-cause row,
e.g. "Cost of Fund exceeds Annual Rate, causing Balance Interest to go
negative."

## UI row labels (generic, no internal team/business terms)

In display order:

1. Annual Rate — % + RM
2. Balance Interest — % + RM
3. After Takaful — % + RM
4. Investor Return — % + RM
5. Team A Return — % + RM
6. Team A Interest — % + RM
7. Team B Interest — % + RM
8. Team B Amount — RM only
9. Per-Head Amount — RM only
10. Monthly Payout — RM only, shown again in the large highlighted final card

("Team A" = sj-prefixed variables, "Team B" = my-prefixed variables — internal
variable names never appear in the UI or in visible strings, only in code
identifiers.)

## UI / visual design

- Dark "trading terminal / ledger" theme: background `#0b0d0c`, accent
  `#d9a441` (amber-gold), monospace font for all numeric values.
- Top card: 4 inputs (Principal, Monthly Rate, Period, Cost of Fund).
  Calculation is live — recalculates on every keystroke, no submit button.
- Middle card: full breakdown list, one row per chain variable, in formula
  order.
- Bottom card: Monthly Payout, visually distinct (amber border, large font).
- All RM amounts formatted with thousands separators and an "RM" prefix,
  2 decimal places (e.g. `RM 31,250.00`).
- Responsive: single-column stacked layout on narrow (mobile) viewports.
- No "demo", debug, or internal-rule explanatory text anywhere in the UI.

## Technical constraints

- Plain HTML + CSS + JS. No frameworks, no build step, no dependencies.
- No database, no localStorage, no service worker, no login/auth.
- Calculation logic implemented as a pure function (no DOM access) so it's
  easy to reason about/verify independently of rendering.

```
PSCalculator/

    ├── icon-192.png
    └── icon-512.png
```

## PWA requirements

- `manifest.json`: name "Profit Split Calculator", short_name "Split Calc",
  display "standalone", background_color/theme_color `#0b0d0c`.
- Icons: 192x192 and 512x512 PNG, simple solid background + letter/symbol
  glyph (generated by a small script, not a design tool).
- `index.html` `<head>`: manifest link, `apple-touch-icon`, `theme-color`
  meta tag (for iOS Safari "Add to Home Screen").
- No service worker.

## Deployment plan

3. `gh repo create PSCalculator --public` under the already-authenticated
   `Tendo9001` GitHub account.
4. Push to `main`, enable GitHub Pages serving from `main` branch root.
5. Report the final `https://tendo9001.github.io/PSCalculator/` URL (exact
   casing/URL confirmed once the repo is created).

## Working process

Confirm with the user after each major milestone (calc logic done, UI done,
repo created, deployed) rather than completing everything in one pass. Flag
any potentially sensitive naming found in code before deciding unilaterally
whether to keep it.
